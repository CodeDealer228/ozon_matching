# Форматирование FRIDA v2

`utils_v2.py` сохраняет inference-пайплайн сабмита `continue_c_llm3m_188`, но меняет текстовое представление товара. Категория остаётся в исходных данных и не передаётся модели.

## Форматы

Старый:

```text
paraphrase: Name: Название товара Category: Категория Attributes: {"цвет товара": "черный", "память товара": "256GB"}
```

Новый:

```text
Название товара
цвет товара = черный
память товара = 256GB
бренд = Samsung
```

Перед сборкой строки в названии товара, ключах и значениях атрибутов:

- все whitespace-последовательности заменяются одним пробелом;
- пробелы по краям удаляются;
- внутреннее ` = ` заменяется на `=`, чтобы не смешивать его с разделителем ключа и значения;
- атрибуты сохраняют прежний порядок приоритетов, но соединяются переводами строки;
- `paraphrase:`, категория, JSON и поиск marker-токенов удалены.

## Локальный benchmark

Измерено на слабой локальной машине по всем 711 304 строкам `items_human.parquet`. FRIDA tokenizer запускался с `max_length=188`, `padding=max_length`, chunk size 14 000; чтение parquet не включено. Абсолютные секунды не переносятся на H100-стенд.

| Этап | Старый формат | Новый формат |
|---|---:|---:|
| Построение строк | 15.68 с | 19.98 с |
| Токенизация | 162.86 с | 143.01 с |
| Всего | 178.54 с | **162.99 с** |
| Средняя длина item | 143.29 | **120.73 токена** |

Новый preprocessing целиком быстрее на 9.5%, а средний item содержит на **15.74% меньше токенов**. Модельное качество PR-AUC ещё не измерено: формат требует ретокенизации обучающих данных и адаптации модели.
