## Что из этого следует

### 1. Разброс AP в 3.1× — на 83 % артефакт prevalence, а не качества модели

`corr(AP, π) = 0.834`. Сырой AP по категориям читать нельзя. Два примера, где
интуиция ломается:

- **Аптека** — AP 0.434 выглядит слабо, но **ROC-AUC 0.909 — второй лучший результат
  из 20**. Низкий AP там чисто механический: при 6.9 % позитивов даже отличное
  ранжирование не даёт высокого AP. Улучшать Аптеку почти некуда.
- **Канцелярские товары** — AP 0.500 в середине таблицы, но **ROC-AUC 0.677 — худший
  из всех 20**. Это скрытая проблемная категория, которую сырой AP маскирует высокой
  prevalence (0.331).

### 2. Настоящие слабые места — fashion + ювелирка, и там же весь доступный запас

По skill-score худшие пять: Ювелирные изделия (0.150), Одежда (0.189), Обувь (0.206),
Мебель (0.213), Канцелярские товары (0.252) при медиане 0.384.

Арифметика запаса: подтянуть все категории ниже медианы до медианного skill →
macro **0.5283 → 0.5725 (+0.044)**; до верхнего квартиля → 0.5892 (+0.061).
При этом **четыре категории (Ювелирные, Одежда, Обувь, Мебель) дают +0.0341 — это
77 % всего реалистичного запаса**. Работа над остальными 16 категориями почти не
двигает метрику.

### 3. Почему они падают: разметка на уровне вариантов, а не моделей

Разбор худших ошибок (`kaggle_kernels/val-per-category-metrics/output/error_samples.txt`)
даёт симметричную картину:

- **False positives** — один и тот же товар, отличается размером / цветом / артикулом,
  и это **негатив**:
  `кольцо из красного золота р. 15 эстет 01к0113743` vs
  `эстет кольцо из красного золота 585 пробы без вставок 01к0113743. размер 18.5` → p = 0.84, label 0.
  `костюм рабочий летний муж. л16-кпк син/вас (р.48-50)` vs `... син/оранж (р.48-50)` → p = 0.95, label 0.
- **False negatives** — один и тот же товар, названия от разных продавцов не пересекаются
  вообще, и это **позитив**:
  `юбка с разрезом цветочный принт` vs `юбка bulatov` → p = 0.05, label 1.
  `poemiq / парные обручальные кольца 375` vs `poemiq кольцо золото красное 585 пробы` → p = 0.06, label 1.

То есть решает не похожесть названий, а конкретные значения атрибутов (размер, цвет,
артикул). Название их либо не содержит, либо содержит в форме, которую модель не видит —
см. п. 4.

### 4. Окно в 128 токенов — связывающее ограничение: атрибуты до модели почти не доходят

**100 % пар обрезаются** (медиана — 445–780 токенов на пару при лимите 128).
При `truncation="longest_first"` на каждый товар приходится ~62 токена. Замер по
выборке из val:

| | медиана токенов |
|---|---:|
| префикс `Name: … Category: … Attributes: ` | **56.5** из 62 |
| атрибутов реально влезает | **0–14** токенов (в 6 категориях медиана = **0**) |
| атрибутов доступно (уже после отрезания по 384 символа) | **146–340** токенов |

В Ювелирных изделиях у **60 % товаров** одно только `name + category` переполняет
бюджет — атрибуты не доходят вообще никогда. В Одежде и Обуви названия короткие
(22–26 токенов), но и там проходит лишь ~11 % доступных атрибутов.

Причина — токенизатор. `ms-marco-MiniLM-L-12-v2` использует английский WordPiece,
который режет русский текст **посимвольно**: `кольцо` → `к ##о ##л ##ь ##ц ##о`,
в среднем **1.33 символа на токен**. Русскоязычный токенизатор при том же окне дал бы
примерно втрое больше содержания.

Отдельно: ~29 % бюджета (медиана 18 из 62 токенов; до 27 в «Музыкальных инструментах»)
уходит на литералы `Name:/Category:/Attributes:` и на **значение категории, которое
у обоих товаров пары одинаково всегда** (проверено: 100 % пар) и поэтому не несёт
ни бита различающего сигнала. Честная оговорка: `corr(эти токены, skill) = +0.44`,
то есть сам по себе этот оверхед **не объясняет** слабые категории — но освободить
его строго выгодно и почти бесплатно.

### 5. Лексический сигнал модель уже вычерпала (отрицательный результат)

`corr(AP, AP_naive_jaccard) = 0.946` — профиль модели по категориям почти повторяет
профиль наивного Jaccard по названиям. Проверка, не осталось ли чего добавить:
ранговый бленд скора модели с Jaccard **монотонно ухудшает** метрику —
0.5283 (w=0) → 0.5253 (0.05) → 0.5218 (0.10) → 0.5136 (0.20) → 0.4704 (0.50).
Бесплатной добавки от лексики нет; сам по себе Jaccard даёт macro 0.355.

## Что делать дальше (по ожидаемому вкладу в macro)

1. **Расширить/перекроить входное окно.** По убыванию соотношения выгода/стоимость:
   (а) выбросить из текста значение `category` и английские литералы — освобождает
   ~29 % бюджета без потери информации; (б) `max_length` 128 → 256; (в) сменить
   энкодер на русскоязычный (`rubert-tiny2`, multilingual MiniLM) — это ещё ~3× по
   содержанию при том же окне. Проверять на 4 слабых категориях: там 77 % запаса.
2. **Взвешивать обучение по категориям.** Метрика — среднее по 20 категориям,
   а лосс сейчас пропорционален пулу. Ювелирка/Одежда/Обувь/Мебель дают вместе
   4/20 = 20 % метрики, но модель на них не сфокусирована.
3. **Явные признаки вариантов** (размер, цвет, артикул из атрибутов) — именно они
   определяют лейбл в слабых категориях, и именно они сейчас обрезаются.
4. Аптеку, Электронику, Музыкальные инструменты трогать смысла нет — там ранжирование
   уже сильное (ROC-AUC 0.81–0.91), а AP упирается в prevalence.

## Воспроизведение

```bash
kaggle kernels push -p kaggle_kernels/val-per-category-metrics          # Kaggle CPU, ~85 мин
kaggle kernels output maxamsecret/ozon-val-per-category-pr-auc-lora \
    -p kaggle_kernels/val-per-category-metrics/output
python scripts/analyze_per_category.py \
    --scores kaggle_kernels/val-per-category-metrics/output/val_scores.parquet \
    --out-dir kaggle_kernels/val-per-category-metrics/output
```

`val_scores.parquet` (id1, id2, label, category, prob, naive_jaccard — 73 131 строка)
сохраняется отдельно, поэтому любую дополнительную нарезку можно считать офлайн,
не платя за новый forward pass.
