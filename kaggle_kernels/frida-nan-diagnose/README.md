# frida-nan-diagnose

Точечная GPU-диагностика NaN-бага в `frida-lora-sft` (loss=NaN на каждом
шаге при fp16). Не тренировочный цикл — несколько forward-проходов на
реальных данных, с хуками на каждый из 24 T5-блоков; укладывается в минуту
GPU-времени.

- **Kaggle:** https://www.kaggle.com/code/maxamsecret/frida-nan-diagnose
- **Тип:** script · **GPU:** 2×T4 · **интернет:** вкл · приватный, владелец `maxamsecret`

## Суть
Локальный CPU-репро (тот же реальный батч, тот же чекпоинт, fp32 и
`torch.autocast(cpu, bfloat16)`) был полностью чистым — значит баг реально
CUDA-специфичный. `attn_implementation="eager"` (в обход fused
SDPA-ядер, первый подозреваемый) тоже не помог сам по себе. Кернел
закрывает оставшиеся переменные напрямую на T4:
1. Веса после загрузки конечны?
2. NaN'ит ли чистый fp32 на GPU без всякого autocast?
3. Если fp32 чист, а fp16/bf16 autocast — нет: хуки на все 24 блока находят
   точный слой первого NaN, отдельно для каждой точности.
4. Один GPU vs `nn.DataParallel` (2 GPU) — реальный обучающий прогон всегда
   оборачивает модель в DataParallel, но это никогда не тестировалось
   изолированно.

## Результат
| Режим | NaN? | Первый плохой блок | loss |
|---|---|---|---|
| веса при загрузке | конечны | — | — |
| FP32, без autocast | нет | — | 0.69255 |
| FP16 autocast (1 GPU) | **да** | `encoder.block.4` | — |
| BF16 autocast (1 GPU) | нет | — | 0.69255 |
| BF16 autocast + `DataParallel` (2 GPU) | **да** | (хуки не переживают DataParallel-реплики) | — |

Ключевая находка: логиты сломанного `DataParallel+bf16` прогона
**побитово совпадают** с логитами сломанного одиночного `fp16`-прогона.
Вывод: `torch.autocast`, открытый в вызывающем потоке, не пробрасывается в
потоки реплик `DataParallel` (`parallel_apply` гоняет `forward()` каждой
реплики в своём потоке — задокументированное поведение PyTorch, а не баг
конкретно этой модели) — реплики молча отрабатывали без запрошенного bf16,
с той же численной картиной, что и сломанный fp16.

Фикс, применённый в
[`../frida-lora-sft-human-only-10-epochs`](../frida-lora-sft-human-only-10-epochs)
и во всех прогонах после: `torch.autocast` открывается **внутри**
`forward()` модели, а не вокруг вызова снаружи — так bf16 остаётся чистым в
каждой реплике.
