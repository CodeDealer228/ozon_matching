# lora-llm-continue-train

Вторая стадия SFT поверх epoch-7 чекпоинта — домешиваем 11.19M мягких
LLM-меток (`matches_llm.parquet`) к человеческому train-сплиту, чтобы закрыть
разрыв val→leaderboard за счёт более широкого охвата каталога.

- **Kaggle:** https://www.kaggle.com/code/maxamsecret/lora-llm-continue-train
- **Тип:** script · **GPU:** 2×T4 · **интернет:** вкл

## Суть
Резюмируем LoRA-адаптер (`is_trainable=True`!) и продолжаем обучение на смеси
`292 523 human + сэмпл matches_llm`. Мягкие метки `[0,1]` идут прямо в
`BCEWithLogitsLoss` без порога. Токенизация — в disk-memmap, RAM-адаптивный
размер чанка.

## Что использовалось
- **Датасеты:** `ozon-ecup-2026-matching`, `ozon-lora-minilm-finetuned`
  (адаптер для резюма), `ozon-lora-llm-token-cache` (предтокенизированный кэш,
  см. [`../publish-token-cache`](../publish-token-cache)).

## Результат
- **`LR=4e-4`, LLM-only, 500K:** регресс до ~0.503, не восстановился →
  слишком агрессивный пик LR + отсутствие якоря к человеческому сигналу.
- **`LR=2e-4` + warmup 0.10 + human-mix, 2M:** ровный рост
  0.51784 → **0.52447** (100%), почти к стартовым 0.5282.
- **Полный 11.48M-прогон:** упёрся в **жёсткий 12-часовой лимит сессии**
  Kaggle (`CANCEL_ACKNOWLEDGED` на ~69% эпохи), но по пути дал новый лучший
  чекпоинт **0.53229 (60%)** — **выше стартовых 0.5282**. Чекпоинт восстановлен
  из output, пока **не опубликован**.

## Ключевые грабли (подробно в CLAUDE.md)
- Резюм адаптера без `is_trainable=True` молча грузит все LoRA-матрицы как
  `requires_grad=False` — жжёт квоту, обучая только голову.
- `items.parquet` (13M) OOM-ит наивный polars-scan: нужен semi-join к нужным
  id **до** строковых операций; `maintain_order="left"` против многомиллионной
  таблицы рвёт RSS — заменён на явный `.sort(row_index)`.
- Linux-OOM-kill **не** ловится как `MemoryError` → размер чанка RAM-адаптивный.
- **Токенизация съела сессию:** train-токенизация 11.48M заняла **~9.54 ч**
  (per-chunk join к 13M items платится сотни раз) → отсюда кэш-датасет и TODO
  «джойнить один раз».
