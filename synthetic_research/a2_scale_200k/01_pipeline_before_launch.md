# A2 v4 all-category 200k — pipeline до запуска

Дата фиксации: 2026-08-25

Ветка: `synthetic`
Цель: 10 000 принятых A2-примеров на каждую из 20 категорий, всего 200 000.

## 1. Что генерируем

Источник каждого примера — реальная human-train пара `(A, B, label=0)`.
Модель переписывает только название товара B так, чтобы оно выглядело как
естественное название маркетплейса и по форме стало ближе к A. Сам товар B,
его марка, модель, артикул, размер, количество и другие факты не меняются.

Чтобы получить достаточную ёмкость для всех категорий, используются обе
ориентации каждой отрицательной пары: `(A, B)` и `(B, A)`. Один запрос может
вернуть до двух разных естественных вариантов названия. В итоговой выборке
сохраняется не более двух вариантов на одну ориентацию.

## 2. Источник и защита от утечек

- Только canonical human train, только `label=0`.
- Canonical split SHA-256:
  `1e3df234d6cdb8685256d5144b25f9a0a3e3a023f1053a0bd5b16c40e3df8d7e`.
- Validation fingerprint:
  `847d04d081432cc081c2149b75271547bf5e25b14f9d8a5804704a5be2a4b3c8`.
- Validation читается только для проверки запретного списка.
- В запрос не отправляются ID, validation, метки и секреты.
- Установленная ёмкость: 190 262 уникальные negative-пары, 380 524
  ориентации. Даже минимальная категория «Детские товары» имеет 21 536
  возможных кандидатов при лимите два на ориентацию, что выше цели 10 000.

## 3. Данные, которые видит модель

Модель получает только:

- категорию;
- название A;
- название B;
- attributes B в компактном виде.

Она возвращает JSON со `status=ok` и одним-двумя вариантами либо
`status=skip`. Reasoning отключён. В декодировании задаётся только
`temperature`; `top_p` не задаётся.

## 4. Проверка результата

Проверка намеренно мягче старого A2 v3 и учитывает замечания тимлида о ложных
отказах. Она не использует рукописный список допустимых обычных слов и не
требует прохождения Frozen Frida.

Кандидат отклоняется только если:

- пустой, совпадает с исходным B или выглядит как служебный ответ модели;
- потерял число, модель или артикул из названия B;
- скопировал число/артикул только из A, не подтверждённый B/attributes B;
- почти не содержит исходных содержательных слов B;
- имеет явные повторы или неестественную длину.

Строковая близость к A считается для диагностики, но сама по себе не является
жёстким фильтром. Это позволяет сохранять естественные перестановки и
морфологические формы вроде «натуральная кожа» → «кожаный».

## 5. Модели и лимиты

Используется точный список моделей, реально возвращённый Alibaba Singapore для
этого аккаунта. Порядок лежит в `model_rotation_v1.json`: сначала самая новая
подходящая модель до 32B, затем следующая.

Модель переключается только после точной ошибки исчерпания allocation/free
quota. Ошибки JSON, длины ответа, сети или rate limit не маскируются под
исчерпание квоты. Автоматических повторов неопределённых запросов нет.

Платный режим автоматически не включается. Поэтому достижение 200 000 зависит
от доступных квот. Если все разрешённые модели исчерпаны, процесс безопасно
останавливается с полным checkpoint и отчётом о фактически набранном объёме.

## 6. Надёжность и наблюдение

- Сырые ответы и журнал отправки дописываются с `flush + fsync`.
- У каждого source есть стабильный SHA-256; уже завершённые или неопределённые
  запросы не отправляются повторно.
- Работа идёт небольшими окнами, чтобы при исчерпании квоты не породить большой
  хвост одинаковых ошибок.
- После каждого checkpoint обновляются counts по категориям и моделям.
- Человекочитаемый Markdown-превью показывает примеры по каждой категории.
- После smoke-test контроль выполняется примерно раз в 30 минут, а не каждые
  10 минут, чтобы не расходовать токены Codex без пользы.

## 7. Порядок запуска

1. Собрать полный source pool и сохранить manifest/SHA.
2. Выполнить dry-run без API.
3. На том же persistent output сделать smoke-test: по одному source на каждую
   из 20 категорий.
4. Проверить JSON, identity-защиту, естественность и человекочитаемый preview.
5. Продолжить тем же output/checkpoint до 10 000 accepted на категорию либо до
   исчерпания всех моделей из registry.
6. Собрать итоговые parquet/manifest/SHA и финальный MD-отчёт.

## 8. Учтённые замечания тимлида из PR #4

- `attributes B` присутствуют во входе.
- Самодельный список разрешённых слов удалён из архитектуры валидатора.
- `top_p` не задаётся одновременно с `temperature`.
- Используется официальный OpenAI-compatible client, а не рукописный HTTP.
- Результаты сохраняются в человекочитаемом виде.
- Шум human-разметки не трактуется как повод строить чрезмерно строгий
  универсальный словарный gate.
