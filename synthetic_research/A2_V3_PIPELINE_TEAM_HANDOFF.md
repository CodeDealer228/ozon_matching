# A2 v3: актуальный pipeline и план масштабирования

## 1. Что мы хотим получить

A2 — это способ сделать реальную отрицательную пару сложнее, не меняя
её правильную метку.

Исходная пара:

```text
(A, B, label=0)
```

После A2:

```text
(A, B', label=0)
```

`B'` — это тот же товар `B`, но его название содержит больше правдивых общих
признаков с `A`. Например, можно добавить цвет, пол или пробу металла, если этот
факт независимо подтверждается у обоих товаров.

Цель — научить Frida не объявлять товары одинаковыми только из-за нескольких
совпавших признаков.

## 2. Неизменяемые правила

1. Источник — только canonical human-train пары с `label=0`.
2. Validation никогда не служит источником генерации.
3. Пересечение train/validation по неупорядоченной паре должно быть нулевым.
4. Qwen не получает ID, validation, полные исходные attributes или ключи.
5. Qwen не может менять марку, модель, артикул, размер, цвет или другой факт `B`.
6. Старые токен-кэши и кэши признаков не используются без строгого identity match.
7. Каждый внешний запуск имеет журнал, SHA-256, запрет дублей и нуль автоповторов.

## 3. Что уже реализовано

### 3.1. Отбор исходных пар

Полный train-скан нашёл:

- 35 109 подходящих human-train negatives;
- 70 218 ориентаций `(A, B)` и `(B, A)`;
- 5 378 строгих Tier A вариантов до категориальных лимитов;
- рабочий пул 400 пар, не более 100 на категорию;
- validation overlap = 0;
- не более одного использования одного item.

### 3.2. Fact contract

Для каждой пары локальный код строит:

- `SAFE_SHARED` — факты, видимые у `A` и независимо подтверждённые у `B`;
- `PROTECTED_B` — числа, размеры, артикулы и модели `B`, которые нельзя потерять;
- `FORBIDDEN_A_ONLY` — факты только из `A`, которые нельзя переносить в `B'`;
- список разрешённых операций.

Нормализация чисел и единиц проверена тестами: `37-38см == 37-38 см`, `20ml == 20 ml`,
но ведущие нули и коды моделей сохраняются.

### 3.3. Qwen generation

- exact model: Alibaba Singapore `qwen3.8-27b`;
- `enable_thinking=false`;
- нуль автоматических retry;
- до одного платного request на source;
- checkpoint по `source_pair_sha256`;
- первый запрос прогревает explicit prompt cache;
- дальше до 6 параллельных worker;
- ответ только JSON: `ok` с кандидатами или `skip`.

### 3.4. Deterministic validator

После Qwen локальная проверка отклоняет кандидата, если он:

- потерял защищённый факт `B`;
- скопировал число, код или факт только из `A`;
- применил неразрешённую операцию;
- изменил identity товара `B`.

### 3.5. Frozen Frida scoring

Для каждого прошедшего кандида считаются:

```text
old_score = Frida(A, B)
new_score = Frida(A, B')
hardening_delta = new_score - old_score
```

Положительный `hardening_delta` означает, что пара стала сложнее для текущей Frida.
Оценка идёт точными весами и тем же препроцессингом, что и сабмит. Старый кэш не
используется.

## 4. Результат первого A2 v3 pilot

Пилот: 20 новых human-train source пар.

### Генерация

|---|---:|
| Запланировано source | 20 |
| Завершённых requests | 20 |
| Transport errors | 0 |
| Uncertain submissions | 0 |
| Model `skip` | 4 |
| Кандидатов | 16 |
| Принято deterministic validator | 13 |
| Отклонено validator | 3 |
| Automatic retries | 0 |

Из 31 047 prompt tokens 25 821 пришли из кэша — около 83%. Completion занял 1 825 tokens.
То есть отключение reasoning и prompt cache работают.

### Безопасность

- 13 из 20 source дали формально и смыслово безопасные `B'`;
- 1 кандидат пойман на копировании факта только из `A`;
- 2 кандидата пойманы на потере защищённого факта `B`;
- 4 сложных автотовара Qwen правильно пропустил.

Вывод: safety gate пройден.

## 5. Почему текущего варианта недостаточно

1. Qwen почти всегда вернул только один вариант. Frida не из чего выбирать.
2. Один тип операции не гарантирует пользу. Добавление цвета дало и `+0,09789`, и `-0,05039`.
3. Важны не только сами факты, но и их позиция в тексте, форма и окружение.
4. Низкая строковая схожесть тоже не предсказывает эффект Frida.
5. Пилот показал разную полезность категорий; равные квоты на этом этапе неэффективны.

## 6. Следующая версия: A2 v3.1

### Шаг 1. Сохранить safety contract без ослаблений

Fact contract, protected facts, forbidden facts, validation leak checks и deterministic validator не меняются.
Эта часть пилот подтвердил.

### Шаг 2. Оценить old Frida score до Qwen

Сначала локально оценить все strict source текущей Frida. Не тратить Qwen на:

- уже очень лёгкие negatives, где небольшое изменение не даст сигнала;
- пары, где Frida уже слишком уверена в match и нет безопасного запаса для hardening;
- категории/операции, которые показали стабильно отрицательный эфект.

Точный диапазон old score не фиксируем по 13 примерам; сначала собираем большую локальную
статистику.

### Шаг 3. Два разных безопасных кандидата

Если hardening возможен, Qwen должен вернуть ровно два варианта:

1. `minimal` — минимальная вставка без перефразирования `B`;
2. `alternate_placement` — те же факты в другой естественной позиции.

Оба кандида проходят одинаковый validator. Нельзя добавлять новые факты ради разнообразия.

### Шаг 4. Frozen Frida выбирает, Qwen не выбирает

Для каждого source оценить оба кандида и оставить лучший только если:

```text
identity_safe
AND negative_safe
AND hardening_delta > 0
```

В training не идут кандидаты с `hardening_delta <= 0`, даже если они красиво выглядят.

### Шаг 5. Новый пилот, а не массовая генерация

Следующий платный шаг — 20–40 новых source из неиспользованной части пула, а не повтор
текущих 20.

Переход к партии 100 разрешён, если:

- critical identity violations = 0;
- validation/source leak = 0;
- transport errors и uncertain submissions понятны и не дублируются;
- accepted source rate >= 50%;
- доля source с лучшим `hardening_delta > 0` >= 60%;
- median лучшего `hardening_delta` > 0.

После каждой партии 100 повторяется полный аудит. Масштабирование идёт ступенчато:

```text
20–40 source pilot -> 100 -> 100 -> ... -> 300–500 accepted A2
```

Если gate не пройден, pipeline останавливается до траты следующей партии.

## 7. Обучение и финальная проверка

Когда набрано несколько сотен принятых A2:

1. Фиксируем manifest и SHA-256 всех synthetic rows.
2. Проверяем дубли, item reuse, category balance и train/validation overlap.
3. Собираем один training set: canonical human train + accepted A2.
4. Все A2 сохраняют `label=0`.
5. Запускаем ровно один сравнительный training run.
6. Оцениваем на untouched canonical validation.
7. Сравниваем с baseline:
   - macro AP: `0.7588808815558529`;
   - micro AP: `0.8132819127479105`;
   - AP по каждой категории.
8. Сохраняем веса, validation predictions, metrics, split/cache identity и submission archive.

Вывод об улучшении делается только по validation после обучения. Frozen Frida hardening — это фильтр
качества synthetic, а не финальная метрика модели.

## 8. Текущее решение

- A2 v3 safety подтверждена.
- A2 v3 effectiveness недостаточна для масштабирования.
- Текущий prompt не запускается ещё на 100+ source.
- Следующий шаг — A2 v3.1: два безопасных варианта, предварительный old-score отбор и обязательный
  Frozen Frida selection.
- Только после прохождения v3.1 gate масштабируем до нескольких сотен и обучаем модель.
