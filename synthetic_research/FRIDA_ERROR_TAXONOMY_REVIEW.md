## Что подтверждено

Для каждой категории рассмотрены 200 наиболее уверенных ложноположительных пар и 200 положительных пар с низкими оценками. Среди 1000 hard-FP пар:

- `379` пар содержат хотя бы одно смысловое различие, которое реально присутствует в exact Frida input;
- обнаружено `515` таких вхождений dimensions, поскольку у одной пары может быть несколько различий;
- `critical_attribute_mismatch` подтверждён как систематический failure mode.

При этом ни одно широкое правило вида «категория + поле» не прошло в C автоматически: для размеров, цветов, артикулов и других полей встречаются human-positive контрпримеры. Поэтому C разрешается только после повторной проверки узкого product family/context на human train.

## Ручная проверка примеров

Проверка exact model inputs подтвердила несколько полезных узких гипотез:

- обувь: одинаковая точная модель при разных размерах может образовывать корректный hard negative;
- ювелирные изделия: одинаковый дизайн/модель при разных размерах, а иногда при согласованном изменении суффикса артикула, может образовывать hard negative;
- одежда: одинаковая модель при разных вариантах цвета или размера потенциально полезна, но требует особенно строгой train-проверки из-за большого числа positive counterexamples.

Также найдены причины не превращать автоматические различия в правила без ручной проверки:

- значения объёма вида `520 ml` и `520` могут быть эквивалентными представлениями;
- названия типа товара могут быть синонимами, а не identity-critical различием;
- конфликт артикула в названии и атрибутах может означать шум данных;
- широкие правила по цвету, размеру и артикулу имеют положительные контрпримеры.

Конкретные validation ID и значения намеренно не фиксируются в generation policy.

## Решение для следующего этапа

### A2

A2 можно строить для всех пяти целевых категорий только из реальных human-train negatives. Меняется только `name`; `attributes` остаются byte-for-byte неизменными. Цель — сделать формулировку второй карточки более похожей на первую, не меняя товар и не перенося факты из первой карточки.

### C

На human train сначала проверяются только узкие гипотезы:

1. обувь: exact model/product family + размер;
2. ювелирные изделия: exact design/model family + размер или связанный с размером article variant;
3. одежда: exact model family + цвет/размер — только если train evidence отделяет negatives от positive counterexamples.

Все три имеют статус `train_verification_required`. Replacement values можно брать только из реальных human-train товаров того же узкого family/context. Глобальные правила `category + attribute` запрещены.
