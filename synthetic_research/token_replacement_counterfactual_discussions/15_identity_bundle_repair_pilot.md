# Identity bundle repair — pilot

## Задача

Переработать уже сгенерированные рискованные brand/article операции из `fast_v2_full_12k_v1`, не повторяя исходную генерацию и не меняя технические характеристики товара.

Из 4 406 операций:

- 1 468 количественных и размерных операций остаются без изменений;
- 2 938 brand/article операций проходят отдельный repair gate.

## Правило ремонта

Старая операция является подсказкой, а не готовой заменой. Для каждой операции восстанавливаются исходные human-train карточки и `evidence_name`, из которого была взята замена. Модель получает только category, names, attributes, предложенные source/target spans и evidence; ID, label, validation и secrets не отправляются.

Structured output разрешает только:

- `keep`, если одиночная замена уже согласована и зависимой модели/линейки нет;
- `repair` с 1–4 отображениями между заранее предложенными точными spans;
- `skip`, если минимальный пакет нельзя подтвердить.

Меняются только бренд, линейка, модель, артикул и их текстовые алиасы. Память, цвет, размер, количество, рынок, процессор, экран, батарея и другие характеристики сохраняются. Отсутствующее поле не добавляется.

## Few-shot correction

Локальный `few_shot_annotation_template_v1.json` проверен до pilot:

- AOS → Fairy изменён на `skip`, потому что одиночный бренд оставлял неподтверждённую линейку/формулу;
- DHT11 → DHT22 изменён на `skip`, потому что модели отличаются характеристиками и target evidence отсутствует;
- Puma → Adidas оставлен как явное generic brand-only исключение без линейки/модели;
- добавлены правила сохранения характеристик и обязательного bundle/skip для brand/article.

Новый локальный SHA-256 few-shot файла: `05628b02319f846ba66461286cd5ba3e804849801a41d29b495d63a6d0652563`.

## Pilot gate

Первый запуск ограничен 100 операциями, сбалансированными по категории и роли. После него вручную проверяются `keep/repair/skip`, согласованность новых названий и отсутствие изменений несвязанных характеристик. Полные 2 938 операций отправляются только после прохождения этого gate.

## Результат pilot v1

Pilot отправлен после commit `19d3b3d`; output: `artifacts/token_replacement_counterfactual/identity_bundle_repair_pilot_100_v1`.

- 100 terminal source operations, повторов нет;
- 8 complete batches / 40 решений;
- 12 terminal batches / 60 операций: 11 `mapping_not_offered`, 1 `decision_count_mismatch`;
- модель вернула 35 `repair` и 5 `skip`.

Строгий локальный разбор 40 решений:

- 12 решений эквивалентны безопасному сохранению исходной точной замены;
- 5 безопасных `skip`;
- 10 repair содержат исходную замену, но добавляют сомнительные изменения;
- 13 repair даже не сохраняют исходную точную замену.

Встречались запрещённые изменения размеров, напряжения, объёма, продуктового типа и общих слов. Например, модель пыталась превратить аккумулятор HP в Acer, сохранив HP-specific модель ноутбука, либо заменить размеры шин вместе с брендом. Поэтому pilot gate **FAIL**, полный запуск v1 запрещён.

После pilot локальный v2 ужесточён: risky role подтверждается только явным атрибутом brand/article; source spans берутся только из identity-bearing атрибутов; каждая repair обязана включать исходное точное отображение, а одиночная repair нормализуется в `keep`. Повторно отправлять 100 source из v1 нельзя. Следующий pilot должен использовать новые непересекающиеся операции.

## Результат pilot v2

Непересекающийся pilot v2 обработал ещё 100 операций:

- 7 complete batches / 35 решений;
- 13 terminal batches / 65 операций: 10 `mapping_not_offered`, 1 `invalid_repair_slot`, 2 повреждённых JSON;
- 20 `keep`, 10 `skip`, 5 `repair` после нового локального gate.

Требование точной исходной замены сработало, но свободные дополнительные mappings всё ещё создают повторы и меняют неидентификационные части: `flight ultra ultra`, `new balance кроссовки new balance кроссовки`, перенос размеров шин, цвета или типа товара. Из пяти repair только единичные article-only случаи выглядят пригодными без ручной правки.

Итог: автоматическое переписывание готовых карточек по одному `evidence_name` не проходит quality gate. Evidence часто относится к другому типу или варианту товара и не содержит полного целевого identity package. Безопасно использовать ответы как `keep/skip`-оценку, но не как свободный текстовый repair. Для настоящего ремонта нужен grounded target package из полной реальной карточки того же product type либо из веб-поиска; затем код должен применять заранее построенное отображение, а LLM — только выбирать его ID.

## Grounded bundle v3

Следующая версия устраняет свободную генерацию mappings. Для каждой рискованной операции код:

1. находит полную реальную human-train карточку, из которой пришёл target token;
2. проверяет категорию, типовой контекст и совместимость бренда для article-only замены;
3. строит готовый пакет только из полей `brand/model/article` с сопоставимыми ключами;
4. изменяет название и только identity-поля attributes; память, цвет, размер, совместимость и остальные характеристики не редактируются даже при буквальном совпадении;
5. отправляет LLM несколько готовых `bundle_id`; structured output разрешает только выбрать один из них либо `skip`.

LLM больше не может сочинять span, модель, артикул или техническую характеристику. Первый gate снова проводится на 100 новых операциях, не пересекающихся с двумя предыдущими pilot.

Grounded dry-run нашёл 1 190 пригодных операций из 2 437 строгих brand/article candidates. В pilot были отправлены 100 новых операций: 85 получили валидный structured response, 65 были `skip`, 20 выбраны, три batch завершились ошибкой формата. Ручной просмотр выбранных пакетов обнаружил остаточные неявные линейки и алиасы бренда (`Mi`, `SMG16`, `Platinum Plus`, `Lotos Ceramic`). Поэтому перед любым масштабированием добавлен локальный запрет: target token обязан присутствовать в title реальной target-card, старый бренд и его транслитерация не должны оставаться, а неперенесённые латинские model/line tokens source должны встречаться в target-card. Повторных API-запросов для этого уточнения нет; исходные 100 решений только переоцениваются локально.

Дополнительно пакет отклоняется, если полная target-card явно противоречит сохранённым характеристикам source по общему полю: цвету, размеру, памяти, объёму, мощности, количеству, габаритам, комплектации и другим защищённым спецификациям. Это исключает, например, перенос артикула розовой укулеле на фиолетовую карточку без изменения цвета.

Финальная локальная переоценка оставила 127 grounded candidates во всём пуле. Из 20 выбранных LLM пакетов пилота строгий gate сохранил 8 и удалил 12; повторных запросов не было. Это качественно безопаснее v1/v2, но объём слишком мал для отдельного заметного training experiment. Поэтому масштабирование repair и обучение на нём не запускаются. Следующий разумный вариант — строить target bundles до генерации из специально подобранных реальных карточек с совпадающими защищёнными характеристиками, а не ремонтировать постфактум случайные операции fast v2.
