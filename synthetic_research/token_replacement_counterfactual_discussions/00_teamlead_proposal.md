# Исходная идея тимлида

## Основная схема

На вход модели приходит случайная human-пара с `target=1`. Эвристика заранее находит несколько общих токенов двух товаров и предлагает модели выбирать только среди них. Модель решает, какой предложенный токен заменить и на какое новое значение.

Для каждой выбранной замены независимо строятся два примера:

- замена в обоих товарах пары — новый положительный пример (`target=1`);
- замена только в одном товаре — новый отрицательный пример (`target=0`).

Поэтому две независимые замены дают четыре синтетические пары: две положительные и две отрицательные.

## Пример

Исходная положительная пара относится к категории «Автотовары»:

```text
name_1: lynxauto фильтр масляный арт. sg1909
attr_1: {
  "артикул": "lynxautosg1909",
  "бренд": "lynxauto",
  "партномер (артикул производителя)": "sg1909",
  "тип": "фильтр масляный",
  "вид техники": "легковые автомобили"
}

name_2: фильтр масляный lynxauto sg1909
attr_2: {
  "артикул производителя": "sg1909",
  "бренд": "lynxauto",
  "цена за": "1 шт.",
  "примечание": "внешний вид изделия может отличаться от фотографий",
  "код товара": "600003292776"
}
```

Ответ модели:

```json
{"lynxauto":"Masuma","sg1909":"w71295"}
```

Каждая запись применяется отдельно, а не как единый пакет замен.

## Обязательные уточнения

1. Нужен structured output: модель должна выбирать исходный токен только из переданного ей списка.
2. Положительная исходная пара допускается к запросу, только если среди общих предложенных токенов есть хотя бы один токен с латинской буквой или цифрой.
3. Модель должна иметь возможность вернуть `skip`, если безопасной и естественной замены нет.
4. Желательно позже вручную собрать по 3–5 few-shot-примеров для каждой категории; для первой реализации это не обязательный блокер.
5. Изменения следует вносить непосредственно в ветку PR №7 `simple_sintize_and_augmentation`.
