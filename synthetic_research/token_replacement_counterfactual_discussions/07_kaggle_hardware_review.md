# Kaggle: доступное железо и реальная применимость для локальной LLM

Дата проверки: 2026-08-26.

## Короткий вывод

Kaggle теперь технически знает существенно больше ускорителей, чем старые P100/T4: официальный CLI перечисляет A100, H100, L4, RTX Pro 6000, TPU v5e-8 и TPU v6e-8. Но часть этих профилей доступна только администраторам или участникам отдельных соревнований. Поэтому наличие имени в API не равно доступности нашему аккаунту.

Для нашего аккаунта уже практически подтверждены:

- `NvidiaTeslaT4` — в репозитории успешно выполнялись T4 x2 kernel;
- `TpuV5E8` — на нём успешно выполнялись текущие TPU-обучения;
- недельная квота на момент проверки: GPU 30 часов, использовано 2.624; TPU 20 часов, использовано 0.988;
- обновление квоты: 2026-08-29 00:00.

Остаток — примерно 27.38 часа GPU и 19.01 часа TPU. Это позволяет делать несколько содержательных экспериментов, а не один сверхосторожный запуск.

## Что перечисляет официальный Kaggle CLI

В документации Kaggle CLI по состоянию на февраль 2026 перечислены:

- `NvidiaTeslaP100`;
- `NvidiaTeslaT4`;
- `NvidiaTeslaT4Highmem`;
- `NvidiaTeslaA100`;
- `NvidiaL4` и `NvidiaL4X1`;
- `NvidiaH100`;
- `NvidiaRtxPro6000`;
- `TpuV38` и `Tpu1VmV38`;
- `TpuV5E8`;
- `TpuV6E8`.

Источник: [официальная документация Kaggle CLI](https://github.com/Kaggle/kaggle-cli/blob/main/docs/kernels.md).

Там же прямо сказано, что некоторые профили предназначены только для отдельных соревнований или администраторов. Read-only метода, который вернёт entitlement конкретного аккаунта на каждую форму машины, в публичном CLI нет. Узнать доступность v6e/H100/A100 для нашего аккаунта можно только коротким отдельным probe-kernel: запросить конкретный `machine_shape`, вывести фактическое железо и немедленно завершиться.

## TPU v5e-8 и v6e-8

Подтверждённый Kaggle TPU v5e-8 даёт восемь чипов по 16 GB HBM, то есть 128 GB памяти ускорителя суммарно. Хост имеет 224 vCPU и 384 GB RAM. Эти значения совпадают с нашими фактическими kernel-профилями и [официальной спецификацией Google TPU v5e](https://cloud.google.com/tpu/docs/v5e).

TPU v6e имеет по 32 GB HBM на чип. Восьмичиповая форма даёт 256 GB HBM и значительно более мощный хост. Спецификация: [Google TPU v6e](https://cloud.google.com/compute/docs/tpus/tpu-machines). Kaggle CLI уже принимает имя `TpuV6E8`, но доступность нашему аккаунту ещё не подтверждена.

## Что это означает для Qwen

1. **Qwen3.8-27B.** Это реалистичный кандидат для отдельного TPU compatibility probe. Вес модели укладывается в суммарную память v5e-8, но нужен рабочий путь `Transformers + PyTorch/XLA` и корректное шардирование между восьмью процессами. Сам факт достаточной суммарной памяти не гарантирует, что новая архитектура скомпилируется без доработок.
2. **Qwen3.8-Flash-Next.** На момент проверки официальная страница открытых весов всё ещё показывает upcoming release 26 августа 2026, поэтому сейчас нельзя честно подтвердить конфигурацию, объём файлов и поддержку TPU. Пока артефакт не опубликован, развёртывание на Kaggle — не план, а предположение. Страница: [Qwen/Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next).
3. **Управляемые Qwen API.** Для генерации они практичнее локального serving: доступны тяжёлые модели, structured output и встроенный веб-поиск. Kaggle в таком случае нужен для обучения и локальных open-weight экспериментов, а не обязан обслуживать всю генерацию.

## Рекомендуемый аппаратный эксперимент

Подготовить два probe-kernel без загрузки приватных данных:

1. `TpuV6E8 hardware probe`: фактический тип TPU, число чипов, HBM, версии JAX/PyTorch/XLA, 30–60 секунд;
2. `best GPU probe`: сначала запросить H100, затем A100 только после доказанного отказа entitlement; вывести `nvidia-smi` и завершиться.

Probe не обучает модель и не скачивает веса. Его цель — отделить реальную доступность от общего списка Kaggle. После этого локальный LLM-путь выбирается по фактам.
