# BERTA-эмбеддинги + PCA(32) + CatBoost — надстройка над `berta/tpu_lora`

**Тест-скор: 0.469** — чуть ниже `berta/tpu_lora` (0.47), но заметно выше
своего непосредственного предшественника без PCA (0.457). Zip:
`matching-berta_catboost_pca32-submit.zip`.

## Что это за решение

Не отдельная модель, а **голова поверх уже готового чекпоинта**
`../tpu_lora/` (`maxamsecret/berta-tpu-lora-top-checkpoint`, тот же 0.47
энкодер). Идея: вместо одного линейного классификатора над
pooled-представлением обучить CatBoost на более богатом наборе фич —
эмбеддинг + собственный скор классификатора + лексический (TF-IDF) сигнал
+ категория. В теории должно давать **прирост** над 0.47; на практике пока
не дотягивает — раздел «Почему не выше 0.47» ниже.

## Признаки, которые видит CatBoost

| Фича | Источник | Размерность |
|---|---|---|
| `pca_0..pca_31` | PCA(32) на pooled-эмбеддинге BERTA (768→32) | 32 |
| `classifier_score` | сигмоида родного линейного классификатора чекпоинта `tpu_lora` | 1 |
| `tfidf_score` | косинусная близость TF-IDF по категории (dot-product trick, `norm='l2'`) | 1 |
| `category` | нативная категориальная фича CatBoost | 1 |

PCA(32) обучен **только на train-сплите самого CatBoost** (не на val, не
на train BERTA — отдельный сплит, чтобы не давать PCA увидеть то, на чём
потом мерится качество). Объясняет 66.66% дисперсии train-эмбеддинга.

## Гиперпараметры CatBoost

```
depth = 6              # было 8 в первой версии без PCA
l2_leaf_reg = 30.0      # было 15.0
bagging_temperature = 1.5   # было 1.0
random_strength = 3.0       # было 2.0
task_type = "CPU"       # локальный retrain, не Kaggle-кернел
```

Обучен **локально**, не через Kaggle-кернел — единственное решение в этом
списке без своего кернела в `kaggle_kernels/`. Отгружен на 1000 деревьях
(лучший val 0.7419 из пяти чекпоинтов 1000/2000/3000/4000/5000 —
val монотонно падал с ростом числа деревьев даже при 32 признаках).

## Логика обрезки текста item'а

Наследуется от `berta/tpu_lora` без изменений — эмбеддинги извлечены
кернелом `berta-top-embed-extract` на том же чекпоинте с тем же
`PAIR_MAX_LENGTH=256` и той же формулой обрезки (см.
`../tpu_lora/README.md` → «Логика обрезки текста item'а»). Здесь ничего
своего в препроцессинге текста нет — вся работа только над уже готовыми
эмбеддингами.

## Провенанс: последовательность кернелов и Kaggle-датасетов

```
maxamsecret/berta-tpu-lora-top-checkpoint (val 0.7087, тест 0.47 — см. ../tpu_lora/)
  │
  ├──▶ kaggle_kernels/berta/training/embeddings/top-embed-extract (1×T4)
  │     — pooled-эмбеддинг (768) + сырой логит классификатора
  │       на val-сплите (73,131 пара, без лика), PAIR_MAX_LENGTH=256
  │     → val_embeddings.npy, val_classifier_score.npy, val_meta.parquet
  │
  ├──▶ kaggle_kernels/retrieval_probes/tfidf-category-index-fit (CPU)
  │     — ~20 маленьких TfidfVectorizer (по одному на категорию),
  │       fit на полном каталоге items.parquet (не per-item векторы —
  │       память безопасна)
  │     → tfidf_vectorizers/ (~20 файлов по 5-15МБ)
  │
  ▼
kaggle_kernels/berta/catboost/catboost-top-final (2×GPU)
  — CatBoost на [768 сырых эмбеддинга + classifier_score + tfidf_score + category]
  → val 0.7467 (лучше чистого классификатора!), но тест 0.457 — ХУЖЕ
    (переобучение: get_feature_importance() показал 96.11% на 768
    почти-шумовых измерениях, classifier_score получил только 1.9%)
  │
  ▼
локальный retrain (без кернела) — PCA(32) вместо 768 сырых + сильнее
регуляризация (см. гиперпараметры выше)
  → val 0.7419 (почти не просел), importance classifier_score выросла
    до 19.3% (в 10 раз), тест 0.469
```

## Почему не выше 0.47: структурная нехватка данных без лика

Чекпоинт `tpu_lora` обучался на человеческом **train**-сплите (292,523
строк, 80%) + `matches_llm.parquet`. Значит без лика для головы поверх его
эмбеддингов годится только **val**-сплит — 73,131 строка, из которых после
80/20 train/val самого CatBoost остаётся **58,504 строки на обучение**. Для
771 фичи (768 эмбеддинга + 3) это мало — то самое переобучение, которое
PCA(32) смягчил, но не решил полностью.

**План дальше (в проработке, не запущено):** закэшировать эмбеддинги на
**всех** 365,654 человеческих парах (train+val), но чекпоинтом, который для
конкретно этих пар не участвовал в обучении — кандидат
`berta-tpu-human-continue-384`. Даёт ~5× больше данных без лика. Кернел
подготовлен (`kaggle_kernels/berta/training/embeddings/embed-cache-all-human`), но не запущен —
ждём подтверждения качества чекпоинта-кандидата на тесте. Полная версия
этого рассуждения — корневой `README.md` → «Известное ограничение: мало
данных без лика для головы поверх BERTA».
